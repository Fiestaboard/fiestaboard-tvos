# User-controlled OLED care

Approved in conversation on 2026-10-24: user explicitly requested implementation on Apple TV and Android/Google TV with TDD, validation and pull requests. This records that approved design and the implementation choices below.

## Intent and constraints
Offer device-local options that may reduce OLED wear without claiming prevention. No new protection enables itself. Existing brightness, drift and panel night-dimming behavior is preserved until explicitly changed. OLED identification is informational: Yes opens configuration; No, Not sure and Skip never change protection settings. All options remain accessible regardless of answer. Do not modify shared server panels or TV firmware settings. Do not claim that black output is standby, that a percentage is physical brightness, or that movement bypasses TV protection.

## Approaches
A single automatic preset would be simpler but conflicts with user control. A page of independent settings and optional setup questions is the approved approach. Static-image detection is deferred; explicit schedules and user-selected disconnect behavior are predictable and testable.

## Settings and behavior
A dedicated OLED care page on both platforms includes a brief optional question: “Will you use this with an OLED TV?” Yes / No / Not sure / Skip. Present an optional setup invitation during setup or on the panel browser; existing users are never forced through it. The page also serves as the configuration flow, with question-style labels and explanations. Choosing Yes alone enables nothing.

- Board brightness: 25%, 50%, 75%, 100% (default 100%). Live sample preview clearly labeled as a preview. This scales app output, not TV hardware brightness.
- Gentle image movement: existing enabled state retained (new installs off), range Gentle (8 output units) / Wider (24). Preview movement and range. Reserve a small safe inset only when movement is enabled, keeping board contents visible even in fill sizing. Do not move UI focus targets. No change to true-size scale unless space is needed to prevent clipping; explain movement can reduce usable area. Reduce Motion must suppress continuous movement; dim/rest remain available.
- Night dimming: preserve Follow panel schedule / Never dim; add a device-local Custom schedule option with start/end and level 10%, 25%, 35%, 50% (default 35%, matching legacy). Equal start/end disables the window; overnight windows supported, start inclusive/end exclusive. Values use TV local time. Do not edit panel schedule from this page.
- Scheduled rest: disabled initially. Start/end selectors (default 22:00–07:00), full black output, release keep-awake request. Explain normal system sleep may follow and automatic wake is not promised. A remote interaction temporarily resumes for 5 minutes so settings remain reachable; then the schedule resumes. Equal times means no rest.
- Periodic breaks: disabled initially. Interval 30/60/120 minutes (default 60), duration 1/5/10 minutes (default 5). Count active foreground viewing with a monotonic clock; do not reset for polls, animations or reconnections. Rest shows black without a persistent logo/text. A remote press resumes and restarts the break interval. Backgrounding pauses the session; no unexpected break immediately upon resume.
- Layout rotation: disabled initially. User selects two or more placements among Center, Upper left, Upper right, Lower left, Lower right, interval 1/5/15 minutes (default 5). Compact the same live board to 80% of available area and change its placement, with no changes to the shared panel contents. Explain this explicitly as board layout/position rotation. One/no selections causes no rotation (provide inline explanation). Honor Reduce Motion via discrete changes; no animated travel required.
- When disconnected: Keep last frame (default), Dim after delay, Rest after delay. Delay 1/5/15 minutes (default 5), dim level uses night level. Covers prolonged connecting/missing/deleted/error display, not just network stale; timing begins at continuous unavailable state, resets on recovery, not failed retries. Full-screen brightness/rest applies to passive status messages as well. Remote interaction provides 5-minute temporary resume; recovery exits outage rest automatically.
- Allow system screensaver: opt-in, default retains legacy keep-awake behavior. When enabled never hold idle inhibition. While resting release inhibition regardless of this choice. Explain OS timing is controlled by device settings and system sleep may return to Home. Do not claim an always-on guarantee; on Android respect system energy saver.

Apply explicit brightness and night dim to board/passive status; keep temporarily summoned controls legible. Rest must hide the board and passive overlays completely. Menus must remain reachable by remote without accidentally activating a button on the same wake press. Restore settings across relaunch; clamp/reject malformed persisted values. Keep device preferences across account sign-out consistent with existing display preferences.

## Validation
TDD for defaults/migration, persistence, schedule boundaries including midnight/equal endpoints, multiplicative dimming, rest precedence, wake override, break cadence, no-input polling, disconnect/recovery, rotation eligibility/selection, geometry at full screen, lifecycle and idle inhibition. Add native UI navigation/persistence tests and actual renderer tests where framework permits. Run existing suites/build/lint, inspect UI previews if possible, and report physical OLED effectiveness as unmeasured. Never claim burn-in prevention from software tests.
