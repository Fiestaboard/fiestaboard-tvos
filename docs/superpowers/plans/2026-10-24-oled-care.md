# OLED Care Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship user-controlled OLED care on this TV platform, preserving existing behavior until the user opts in.
**Architecture:** Persist a device-local care configuration, evaluate a pure policy with explicit local/monotonic time, and apply its result at the viewer boundary. Native settings expose every control with live previews; app lifecycle owns idle inhibition.
**Tech Stack:** Swift, SwiftUI, Foundation, XCTest
**Spec:** ../specs/2026-10-24-oled-care.md

## Global Constraints
No new protection enables itself. Existing display preferences migrate without loss. No server writes from OLED care. OLED answer never applies settings. All protection timers are driven by explicit time and do not reset on data polls. Core contains no UI dependencies. No burn-in guarantees.

## Review Focus
- Settings saved by older versions, malformed data and unknown enum cases preserve usable defaults.
- Rest covering midnight, daylight-saving/local-clock changes and remote wake cannot trap navigation.
- Viewer recreation/reconnection/polling must not reset timers; backgrounding must release idle inhibition.
- Full-size matrix/split-flap content remains visible during wider movement and rotation.
- All unavailable states and passive indicators must respect explicit brightness/rest while summoned controls remain usable.
